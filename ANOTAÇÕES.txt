Sempre que for começar um projeto DJANGO:

1- CRIAR UM AMBIENTE VIRTUAL: <python -m venv venv> 
2- Ativar O AMBIENTE VIRTUAL NA MÁQUINA: <.\venv\Scripts\activate>
3- INSTALAR O DJANGO: <pip install django>
4- CONFERIR QUE O DJANGO FOI INSTALADO: <django-admin --version>

INICIANDO O PROJETO NO DIRÉTORIO:

1- <django-admin -startproject (nome_projeto) .>
2- TESTANDO SERVIRDOR DJANGO: <python manage.py runserver>
3- COMANDOS QUE O DJANGO DISPONIBILIZA: <django-admin --help>

CRIANDO UMA APP:
1- <python manage.py startapp (nome_app)>
2- Adcionar na linha de comando na pasta <app> <settings>, o nome do app que vc criou <cars>

ENTENDENDO AS CAMADAS SIMPLES DO APP:

1- O usuário acessa uma URL, o Django identifica a rota, direciona para uma view, busca ou processa informações por meio dos models e devolve a resposta ao navegador.

2- Estrutura Inicial da App:

`apps.py`: concentra configurações básicas da aplicação e utiliza a classe `AppConfig` fornecida pelo Django.
`tests.py`: serve para escrever testes unitários e de integração, embora seu uso seja aprofundado mais adiante.
Organização por apps: permite separar logicamente partes do projeto, como carros e vendedores, mantendo cada domínio com seus próprios arquivos e responsabilidades.
Modelagem e Lógica da Aplicação:

`models.py`: define os modelos de dados, equivalentes à estrutura das tabelas do banco, incluindo campos como nome, ano e modelo do carro.
`views.py`: concentra a lógica necessária para atender às solicitações, como listar os carros e preparar os dados que serão exibidos ao usuário.
`admin.py`: relaciona a app ao painel administrativo do Django, onde administradores podem realizar operações de CRUD sobre as entidades cadastradas.
Fluxo entre as Camadas:

URLs: interpretam o endereço acessado, como `/admin`, e determinam qual view deve atender à requisição.
Views e models: a view funciona como intermediária, consultando os models, que por sua vez se comunicam com o banco de dados para recuperar ou alterar informações.
Admin e rotas: a URL do painel administrativo também é configurada no arquivo principal de URLs e pode ser personalizada, embora a aula use essa alteração apenas como demonstração.
